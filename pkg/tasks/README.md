# Task runner

Пакет `internal/tasks` выполняет фоновые задачи из PostgreSQL и поддерживает несколько реплик приложения.

## Поля задачи

- `Source` — тип задачи и имя зарегистрированного handler-а, например `avito.analytics.hour.sync.v1`.
- `SourceID` — идентификатор конкретной работы внутри `Source`. Пара `Source + SourceID` является первичным ключом и обеспечивает идемпотентный `Enqueue`.
- `SerialKey` — опциональный ключ последовательного выполнения. Разные задачи с одинаковым непустым ключом образуют FIFO-очередь и не выполняются одновременно даже на разных репликах. Ключ действует глобально для всей task-таблицы и может объединять разные `Source`.
- `Payload` — входные данные handler-а в JSON.
- `RunAt` — самое раннее время запуска задачи.

`SourceID` и `SerialKey` решают разные задачи. Например:

```go
tasks.Task{
	Source:    "avito.analytics.hour.sync.v1",
	SourceID:  accountID.String() + ":" + integrationID + ":" + period.Format(time.DateOnly),
	SerialKey: accountID.String() + ":" + integrationID + ":analytics",
	Payload:   payload,
}
```

Здесь каждый час имеет собственный `SourceID`, поэтому повторная постановка того же часа не создаст дубликат. Общий `SerialKey` не позволяет двум разным часам одной интеграции выполняться одновременно.

Период нельзя добавлять в `SerialKey`: тогда каждая задача получит отдельную группу и ограничение параллелизма исчезнет.

## Жизненный цикл

1. `Enqueue` создаёт задачу в `pending`. Конфликт по `Source + SourceID` игнорируется вместе с новым payload, временем и serial key: существующая задача не изменяется. `Ensure` ведёт себя так же, но возвращает `failed`-задачу в `pending` с новым payload и сброшенным счётчиком попыток.
2. Runner выбирает готовые задачи через `FOR UPDATE SKIP LOCKED`.
3. Задача переводится в `running`, получает `lease_until`, а её `attempt` увеличивается. Пока handler работает, runner периодически продлевает lease.
4. Успешная попытка переводит задачу в `completed`.
5. Ошибка возвращает задачу в `pending` с экспоненциальной задержкой либо переводит в `failed` после `MaxAttempts`.
6. Если runner аварийно завершился или перестал продлевать lease, другая реплика получает задачу после истечения lease.

Завершённая с опозданием попытка не может перезаписать результат новой попытки: операции завершения проверяют текущий `attempt`.

## Последовательное выполнение

Для каждого непустого `SerialKey` claim выбирает только самую раннюю задачу в состояниях `pending` или `running`. Следующие задачи группы остаются недоступны, пока первая не перейдёт в `completed` или `failed`.

Повтор задачи также блокирует следующие задачи группы. Это защищает сценарии, где порядок важнее скорости, например вычисление часовой статистики из накопительных снимков.

Порядок определяется временем создания задачи, затем `Source` и `SourceID`. Поэтому связанные задачи нужно ставить в логическом порядке. Задача с будущим `RunAt`, стоящая первой в группе, блокирует последующие задачи этой группы до своего запуска и завершения.

Пустой `SerialKey` не вводит никаких дополнительных ограничений.

## Параллелизм

- `Config.Concurrency` ограничивает суммарное число handler-ов на одной реплике.
- `SerialKey` ограничивает одну логическую группу сразу между всеми репликами через PostgreSQL.

`Config.Concurrency` масштабируется вместе с количеством реплик. Ограничение `SerialKey` остаётся единичным для всего сервиса.

## Shutdown

При shutdown runner прекращает claim новых задач и ожидает завершения активных handler-ов. Если процесс завершается аварийно, задачи восстанавливаются после истечения lease.

## Гарантии и требования к handler-у

- Семантика выполнения — at least once, а не exactly once.
- Handler обязан быть идемпотентным либо защищать бизнес-изменение уникальным ключом/транзакцией.
- Handler обязан завершаться после отмены переданного context.
- `LeaseDuration` — не максимальная длительность задачи, а срок подтверждения жизни runner-а. Пока handler работает, runner продлевает lease каждые `LeaseDuration / 3`.
- `SerialKey` гарантирует отсутствие одновременного выполнения внутри группы, но не заменяет идемпотентность.
